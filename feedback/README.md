# 运行回执

新对话跑完一次炼化，如果中间有卡点、绕路、被用户否掉的地方，**往这里写一条**。

写的目的只有一个：让下一次的我（或别的 AI）知道哪儿不好使，而不是每次都重新踩。

## 文件名

`YYYY-MM-DD.md`，一天一个文件，多次运行往后追加。

## 每条格式（六行，不多写）

```md
## 14:30 | 文档区 | 200 页扫描版论文

- **卡点**：markitdown 只出 87 字符，原文 200 页 → 判为扫描件
- **试过**：截图 + 多模态直读；本机无截图命令，改请用户手工导出
- **结果**：只读了前 20 页，其余进未读清单
- **建议**：DOCUMENT.md 的降级链补一句"截图从哪来"
- **归属**：skill 缺口
```

## 归属只有四选一（这一行决定怎么改）

| 归属 | 含义 | 后续动作 |
|---|---|---|
| `skill 缺口` | 规则没写清 / 少了某步 / 模板不够用 | 改对应的 references 文件 |
| `环境缺工具` | 需要的东西本机没装 | 改 `TOOLS.md` 的能力边界与降级路径 |
| `材料本身残缺` | 原件就缺页、扫描糊、逻辑不完整 | 不改 skill，在产物里标未覆盖即可 |
| `我判断错了` | 分区/定档/取舍判断失误 | 改判据措辞，别改结论 |

## 什么不算卡点，不要写

- 正常完成、没有绕路的（写了只是噪音）
- 一次就能解决的语法错误（重试即可）
- 用户的个人偏好（那属于 `METHOD.md`，不是回执）

## 谁来读

**开工前先看 `ls feedback/`**：有比上次新的文件，先读一遍再动手——里面可能是别人踩过的坑，也可能是上次的自己留给这次的提示。

## 谁来改

读到 `skill 缺口` / `环境缺工具` / `我判断错了` 三类，按 `PLAYBOOK.md` 的「自优化的变更纪律」判断能不能改、改哪儿，改完 commit + push。
