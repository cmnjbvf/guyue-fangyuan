# 00 总图：先判它是什么构成

分类是为了少读文件，不是为了分类本身。**判错区的代价很小**（换一份手册再读）；**一次读全部的代价很大**（上下文烧掉一半，注意力被稀释）。

## 三问定位

> **判区之前，先判数据源。** 任何东西在电脑上只可能留在五类数据源里：文件 / 系统数据 / 应用数据 / 网络流量 / 内存运行时。
> 先问"它的痕迹在哪一类"，再问"它是什么载体"——顺序反了会漏掉最容易消失的那部分（内存与网络）。
> 详见 `ARTIFACTS.md`。

**第一问：它是字、是图，还是机器码？**

- 能直接读出文字 → 字
- 只有画面，识别后才有字 → 图
- 能运行但读不了 → 机器码

**第二问：是一个文件，还是一个工程？**

- 一个文件 → 单件，直接炼
- 有目录结构、多个文件互相引用 → 工程，先摸形状

**第三问：它是原始材料，还是别人加工过的？**

- 原始材料（源码、原始录音、原始聊天、原始 PDF）→ 直接炼
- 二手加工（别人的架构解析、书评、评测、总结帖）→ **先剥掉加工层**，找它引用的原始材料；拿不到原文就在产物上标"二手，未经原始材料验证"

第三问最容易被跳过，也最容易产出垃圾：拿一篇《XX 项目架构解析》去炼代码规则，炼出来的是作者的理解，不是程序的真相。

## 落在哪一区

| 你看到的 | 区 | 备注 |
|---|---|---|
| `.md` `.txt` 纯文字，无版式 | 文本 | |
| `.pdf` 有文字层 | 文档 | 拿不准先试提取一段 |
| `.pdf` 扫描/纯图 | 文档 | 要版面解析，见 DOCUMENT |
| `.docx` `.pptx` `.xlsx` | 文档 | |
| 单张图 / 截图 | 文档 | 以字为主 → OCR；以场景为主 → 视觉描述 |
| 单个脚本（`.py` `.ts` `.go`…） | 代码 | 直接读，不上工具 |
| 带 `.git` 或 `package.json` 的目录 | 代码 | |
| `.exe` `.dll` `.so` `.apk` `.asar` `.bin` | 软件 | |
| 安装包（`.msi` / 内含程序的 zip） | 软件 | 先看包清单再决定 |
| 聊天导出（`.txt` `.json` `.html`） | 对话 | |
| 工单 / 评论 / issue 导出 | 对话 | |

**跨区的情况**：一个 APK 里既有代码又有资源又有配置。按"最外层是什么"进区，进去后按需借用另一区的手法。**不许因为"它里面还有代码"就同时读两份手册。**

**如果载体是"一个人"（对方的方法、对方的写法、对方的判断方式）→ 不炼，先分流**：

| 你要的产物 | 走哪 |
|---|---|
| **一个能扮演对方的顾问**（"用对方的视角看这个问题"） | 交给 `nuwa-skill`（女娲，677 行，专门造人物 Skill） |
| **一套去人格化的可执行规则**（"对方的判断流程是：先查 A，A 不成立才看 B"） | 女娲造完 → 回本技能，用 `TAKE.md` 的五维把"人"炼成规则 |
| 只是想知道"他会怎么看这件事" | 直接答，别启动任何流程 |

**为什么不在本技能里重写一套**：女娲那边已有完整流程（深度调研 → 思维框架提炼 → 生成可运行 Skill → 更新与品味守则）。按铁律 9，同类能力别人做了就指向它。**本技能只负责"把人格化的东西焊成流程"这一段，那正是女娲不做的事。**


## 混合输入

一次来多种：按"先小后大、先易后难"排序，逐个炼，不并成一个巨型任务。每炼完一个出一份小结，最后合并。

合并时才处理跨材料的冲突——单件炼化阶段不要提前操心别的东西。

## 什么时候不要炼化

- 只是问一个问题 → 直接答
- 只是格式转换 → 直接转
- 只是找一段内容 → 直接搜
- 用户要的就是那份材料本身 → 别动它

炼化只在"要把外部的东西变成自己能用的零件"时发生。用错地方就是过度劳动。

## 目的地维度（和输入维度是两回事）

五区判的是"原料是什么"。另有一个独立维度是**"炼出来的东西要放哪去"**：

| 目的地 | 做法 |
|---|---|
| **领域知识库**（既有体系） | 叠加读 `domain-profile.md`：走该库的合同、同步入口与门禁。只在明确要进这个库时加载 |
| 其他项目目录 | 沿用该项目的文件结构与命名，不套该领域的目录约定 |
| 未指明 | 先在对话里交付结果；要落盘时再确认目标 |

**两者不许混。** "这份 PDF 讲的是该领域"不等于"要进领域知识库"——前者是原料题材，后者是落地目标。

## 判定不改标准

判错区只是换工具，不换标准。三条底线在任何区都一样：

1. 结论要有落点
2. 观察 / 推断 / 未知分开
3. 不假装读过
