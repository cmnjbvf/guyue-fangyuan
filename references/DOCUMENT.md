# 文档区：PDF、Word、PPT、Excel、图片、扫描件

> **什么时候读**：进来的是**带版面的文档**（PDF、Word、PPT、Excel、图片、扫描件）时读——需要先提取文字与结构。拿到纯文字后按 `TEXT.md` 的判法炼。

进来的是**版面**：内容装在容器里，带页、带表格、带图。本区动词是"提取"——先拿到文字与结构，再按文本区的判法炼。产物必须带页码 / 段落 / 单元格级落点。

## 1. 判定

三条同时满足进本区：

1. 文件是容器格式（PDF / DOCX / PPTX / XLSX / 图片），不是裸字符流
2. 直接 Read 看到的是二进制或乱码，必须提取才能读
3. 有版面坐标可引用：页码、段落号、`sheet!单元格` 至少占一样

路由边界：.docx 里其实是代码清单 → 代码区；安装包 / ASAR / 固件 / APK → 软件区（references/SOFTWARE.md）。

### 四个容易误判

- **改名文件**：.docx 实际是 HTML（中文办公室常见），.pdf 实际是 Word 打印件，.xlsx 实际是 CSV 改名（提取结果只有一列长串时改按文本区处理）。读文件头：`PK\x03\x04` = zip 系（docx/pptx/xlsx），`%PDF` = PDF，`\xD0\xCF\x11\xE0` = 老二进制 OLE（.doc/.xls/.ppt）。
- **老二进制三件套**：.doc/.xls/.ppt 不是新格式。markitdown 只认 zip 系，遇 OLE 直接报缺口，给两条路：用户用 Office/WPS 另存为新格式，或走 tencent-docx 技能试读。
- **混合 PDF**：同一文件前 10 页有文字层、后 30 页是扫描图。按页判，不按文件判。

## 2. 取料

主力工具只有一件：

```bash
"C:/Users/<user>/.workbuddy/binaries/python/envs/default/Scripts/markitdown.exe" <文件> -o <输出.md>
```

实测装好：**pdf / docx / pptx / xlsx**。未装：音频转写、EPUB、YouTube——别对这些格式派活。

| 格式 | 路线 | 注意 |
|---|---|---|
| PDF 有文字层 | markitdown 直转 | 转完先验货再拆 |
| PDF 扫描件 | markitdown 会输出空 / 乱 / 一行一字 | 检出即停，报缺口；降级路径见下 |
| Word（docx） | markitdown | 保留标题层级，那是结构骨架 |
| PPT（pptx） | markitdown | 一页一单元，演讲者备注一起取 |
| Excel（xlsx） | markitdown 或 `mcp__sheetagent__read_table` | 大表用 sheetagent，能按单元格区间定位 |
| 图片（png/jpg/截图） | 多模态直读为主，markitdown OCR 试一次 | OCR 失败标 unknown，不许猜图上文字 |

取料纪律：

1. 提取结果与原件分开存放；提取文件是唯一判读对象，原件只读不改。
2. 每页 / 每表 / 每图记录来源坐标：PDF 记页码，Excel 记 `sheet!区域`，图记文件名；没坐标的提取结果不进判读。同一批资料固定一条提取路径，不许一个文件一个解析器。

**文字层体检，每份必做。** 四项检查，任一不过就走降级：

1. **空**：输出 < 100 字符但原件明显有内容 → 疑扫描件
2. **乱**：乱码字符（锟斤拷 / □ / �）占比 > 2% → 编码或字体问题
3. **碎**：一行一两个字、章节顺序颠倒 → 版面解析失败
4. **缺**：页数 / 表数 / 图数与原件目测不符 → 提取不完整

扫描件降级路径，按序尝试，不成的如实报缺口：页面截图 → 多模态直读 → 只判能看清的部分，其余进未读清单。截图获取用 pdf 技能或请用户手工导出；**本机没有 MinerU，别派它的活**。

## 3. 拆到什么粒度

单元 = 一个版面元素或一个语义完整块。先按版面切，再按语义修。

| 格式 | 一级切分 | 单元定义 | 单元上限 |
|---|---|---|---|
| PDF | 页 → 节 | 一页内的一个正文块 / 一张完整表 / 一个图 + 图题 | 正文 1500 字符；表不限行但同表头 |
| Word | 标题层级 | 一节 = 一个单元；无标题长文按 1500 字符切 | 1500 字符 |
| PPT | 幻灯片 | 一页一单元，标题 + 正文 + 备注合并判 | 一页 |
| Excel | 工作表 | 一个逻辑表 = 一个单元；> 500 行按 500 行块切，表头每块重复 | 500 行 |
| 图片 | 单张 | 一张一单元；长截图按内容段落切 | 一张 |

硬数字：

- 跨页表格拼回一个单元：表头页 + 延续页合并判，不许判成两张表；表头丢失的延续页整页标 unknown。表格判断落在行：一行 = 一条可判记录；列口径（单位、时间、分母）从表头取，表头不清整表降级。
- 图与引用它的正文段绑在一起判；孤立无引用的图单独成单元，标"无上下文"。

## 4. 判什么

每单元按序回答七问，答不出写 unknown；没有消费者的主张标 `待判`，单列：

1. **什么版面元素**：正文 / 表 / 图 / 公式 / 代码 / 页眉页脚噪声。页眉页脚不进主张。
2. **提取质量**：本单元乱码率、断行、缺字。质量不达标，内容判 unknown、质量本身判观察。
3. **说了什么**：一句可证伪的主张；表格单元落到"这一行说明什么"。
4. **口径**：数字的单位、时间点、分母、统计范围。缺口径的数字是废的，标 unknown。
5. **成立 / 失效条件**：同文本区第 2、3 问。
6. **什么档**：观察 / 推断 / 未知。OCR 读出的字再清楚也标观察并注明 OCR；跨页拼合的结论标推断。
7. **落点**：PDF 记页码 + 段落序，Word 记标题路径 + 段号，Excel 记 `sheet!A1:D50`，图记文件名 + 区域。**没有页码映射工具时禁止编页码**——用提取文本的字符区间代替并注明"原件页码未映射"。

## 5. 装成什么

**模板 A：事实卡**（数值主张用）

```json
{"id":"fact-<短名>-<n>","statement":"带口径的一句主张","value":{"指标":"值","单位":"","时间点":"","分母":""},"kind":"fact","evidence":[{"page":12,"quote":"逐字","area":"表2 第3行"}],"uncertainties":["口径缺失项"]}
```

**模板 B：表结构卡**（整表还原用）

```json
{"id":"table-<短名>-<n>","location":"P14 表2 / sheet!A1:D50","header":["列名原文，不许改写"],"merged_cells":["合并格子及跨度，无则 []"],"rows":[{"cells":["逐行原文"],"claim":"这行说明什么"}],"continuation":{"from_page":14,"to_page":15,"joined":true}}
```

**模板 C：文档结构图**（导航对账用）

```json
{"id":"map-<短名>","total_pages":30,"tree":[{"title":"标题","page":3,"units":["单元ID"],"claims":5}],"figures":[{"name":"图3","page":8,"cited_in":[10,12],"unit":"单元ID"}],"unread_pages":[17,18]}
```

**模板 D：规则卡**（"学会它""照着做"用）

```json
{"id":"rule-<短名>","statement":"可直接执行的规则表述","kind":"fact","evidence":[{"page":12,"span":[340,412],"quote":"原文"}],"conditions":["仅当…"],"exceptions":[],"uncertainties":[],"consumer":"决策树哪一支 / 检查表第几条"}
```

字段与 `TEXT.md` 的规则卡一致，只把落点换成**页码 + 字符区间双坐标**（页码给人看，区间给程序核）。

**跨页综合出来的规则，`kind` 默认 `inference`**——只有单页能直证时才标 `observed`。这条最容易被跳过：一份 PDF 里散落三处才拼出一条规则，拼的动作是推断，不是原文。

收据结构与 batch-processing.md 对齐：evidence 换成版面坐标（页码+字符区间双落点），kind 用其五类词表（观察→`fact`、推断→`inference`、未知→`unknown`）。**本区收据是概念模板，不走 digest_batch.py 校验**——脚本只认字符区间。两个区的卡进同一个库，形状不许分叉。

## 6. 量化标准

| 指标 | 达标线 | 核法 |
|---|---|---|
| 页覆盖率 | 已判页 / 总页 ≥ 95%；扫描件按已取得页算分母 | 对照结构图 unread_pages |
| 表还原率 | 表格 100% 有表头、有 continuation 判定 | 逐表查表结构卡 |
| 乱码率 | 全库 < 2%；单元级超 2% 该单元降级 | 乱码字符 / 总字符 |
| 坐标落点率 | 事实卡 100% 带页码或区间 | 逐条核；无映射的必须带"未映射"标注 |
| 图-文配对率 | 被引用的图 100% 找到 cited_in | 对照结构图 figures |
| 数字口径率 | 带数值的主张 100% 有单位 / 时间点 / 分母 | 逐条查事实卡 |

批量文档逐文件对账，没对完不许说"全部完成"。机械完成只证明页都有去向、引文逐字一致；语义质量恒标 `not_machine_verified`。

## 7. 失败模式

| 失败 | 症状 | 正解 |
|---|---|---|
| 扫描件当文字层 | markitdown 输出空白或一行一字，还硬着头皮"总结" | 先跑文字层体检；不过即停，报缺口 + 降级（截图多模态读），拿不到标 unknown |
| 表格结构丢失 | 合并单元格变乱行、表头对不上数据、跨页表断成两半各判一个结论 | 用表结构卡逐行还原；一级切分先按表格跨页合并；拼不回标 unknown，不许猜格子归属 |
| 页码造假 | 产物写"见 P12"，但提取文本没有页码映射，凭印象写 | 没映射工具就用字符区间并注明；编页码属最严重失败 |
| 图片当空气 | 所有图被跳过，而核心论据在图里 | 图绑定引用它的正文；孤立图单独判并标"无上下文" |
| 老二进制硬啃 | 对 .doc/.xls/.ppt 反复调 markitdown，得到错误或空 | 文件头认出 OLE 即报缺口，给"另存新格式 / tencent-docx 试读"两条路 |
| 大表只看头部 | Excel 读前 50 行就说看完了，底部合计行、异常行全漏 | > 500 行按块切、表头每块重复；合计行与空行异常单独判 |
