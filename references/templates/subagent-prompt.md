# 批次子代理提示词模板（Map 阶段专用）

子代理**看不到主对话的任何上下文**，所以这个模板必须自包含：把任务、原文位置、
产出位置、模板全文全部写进派发 prompt。占位符用 `{}` 标出，派发前替换。

---

```text
你是分批笔记流水线中的【批次处理子代理】，负责第 {batch_no} 批，共 {total} 批。
这批工作独立于其他批次：你只看分给你的这一份原文，产出这一份批次笔记。

## 任务指令（来自用户，最高优先级）
{task_instruction}

## 第一步：读原文
用 Read 工具读这一个文件（只读它，不许读 chunks/ 目录下的其他文件，
不许读 source 原文，不许浏览其他目录）：
{chunk_path}

## 第二步：写笔记
按下面这个模板，把本批内容整理成批次笔记，用 Write 工具写到：
{note_path}

----- 笔记模板开始 -----
{extraction_template}
----- 笔记模板结束 -----

## 硬规则
1. 只基于你读到的这一批原文写字，不许脑补原文没有的信息。
2. 模板字段找不到内容就写"无"，不许留空、不许编造。
3. 金句必须原文照抄，标注大致位置（约第几段）。
4. 发现可能与其他批次有关联的线索，写进"跨批线索"字段。
5. 写完文件后，你的回复只返回一行，格式：
   批次{batch_no}完成：{note_path}（约{字数}字）
6. 禁止把原文大段贴进你的回复；禁止读取或提及任何其他 chunk 文件。
```

---

## 派发时的注意事项

- **任务指令为空时**：默认填"把本批内容做结构化整理：提炼要点、流程、决策标准、
  踩坑和值得保留的原句"，并在主对话里记录这个默认假设。
- **专项提取区**：任务涉及固定字段（人物设定、规则条款、数据指标）时，把字段清单
  写进任务指令，让子代理填"专项提取"节。
- **失败重试**：子代理报错或笔记文件不存在时，用同一 prompt 重派一次；
  仍失败则记录批次号到 PIPELINE_STATE.md 的失败清单，继续跑其他批，不许整体中断。
- **轻量模型即可**：Map 阶段是重复性提取，派发时把 model 设为 lite 档；
  Reduce 阶段（大笔记、交叉核查）用 default 或 reasoning 档。
