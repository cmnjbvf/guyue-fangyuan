# 蒸馏引擎：从材料里提炼出"能用的东西"

**这份文件解决什么**：把"蒸馏"从若干种各干各的配方（蒸人的、蒸书的、蒸作者的、蒸技能的），收敛成**一套骨架 + 可替换的参数**。看一眼就知道任何对象该怎么蒸。

**和 `distillation.md` 的分工**（别混）：

| | 管什么 |
|---|---|
| `distillation.md` | **资料消化**：从证据到知识项，主张怎么标、条件怎么绑、冲突怎么留 |
| **本文件** | **能力复刻**：从一个人 / 一本书 / 一套本事里，抽出能拿去用的规则和判断 |

---

## 零 · 先分清三个词（混了必出事）

| 做法 | 干什么 | 产物 | 值多少 |
|---|---|---|---|
| **转述** | 把长的说短 | 摘要 | 几乎为零，用户还得回去读原文 |
| **描述** | 说清"它长什么样" | 特点清单 | 低。看完仍不知道怎么做 |
| **蒸馏** | 抽出"它凭什么这么做" | **可执行规则 + 判断标准 + 边界** | 高。拿到就能用，还能迁移 |

**判据一句话**：产物里有没有「**如果 X 就 Y**」和「**不适用的情况**」？
没有 → 你做的不是蒸馏，是描述。

### 三层深度（决定值多少钱）

| 层 | 抽出什么 | 例子 | 能不能迁移 |
|---|---|---|---|
| **现象层** | 表面特征 | "他句长短、爱用比喻" | ❌ 换场景就废 |
| **规则层** | 条件→动作 | "他先问对方的目标，再问约束，最后才给方案" | ✅ 同类任务都能用 |
| **原理层** | 为什么这么做 | "他相信'没搞清目标之前给方案等于浪费对方时间'" | ✅ 跨领域都能用 |

**目标永远是往上爬一层。** 停在现象层的蒸馏，只是换了个说法的描述。

---

## 一 · 六步骨架（任何对象通用）

```
① 取样   → ② 分层   → ③ 提炼   → ④ 对撞   → ⑤ 验证   → ⑥ 封装
   够多        分四层       抽规则        找反例        能证伪       能直接用
```

### ① 取样：多少才够

| 对象 | 最低样本 | 为什么 |
|---|---|---|
| 一个人 | **5–10 份**不同场景的材料（不是同一件事说五遍） | 单场景无法区分"对方的方法"和"这次的处理" |
| 一位作者 | **3 本以上**已完结作品 | 一本书可能是特例，三本能看出稳定模式 |
| 一套方法论 | 原著 + 至少 2 篇解读/批评 | 只看原著会漏掉它被误用的地方 |
| 一个技能/系统 | 完整定义 + 至少 3 次真实使用记录 | 光看定义看不出它什么时候失灵 |

**取样铁律：要"跨场景"，不要"同场景多次"。** 同一个访谈里说十遍的，还是那一件事。

### ② 分层：四层，从浅到深

| 层 | 抽什么 | 抽不到会怎样 |
|---|---|---|
| **语言层** | 句长节奏、比喻体系、口癖、专业词密度 | 产物"像"但不是他 |
| **结构层** | 他组织内容的固定形状（先结论？先故事？三段式？） | 换个题目就散架 |
| **判断层** | **提问顺序 + 判断标准 + 优先级** | **产物没有灵魂，只剩壳** |
| **价值层** | 他在乎什么、反对什么、愿意付出什么代价 | 遇到冲突情境就选错 |

**四层里，判断层是本体，价值层是根。** 只有语言层和结构层的产物，叫"模仿秀"。

### ③ 提炼：七种具体手法

| # | 手法 | 怎么抽 | 产出长什么样 |
|---|---|---|---|
| 1 | **提问顺序** | 看他遇到新问题**先问什么、后问什么** | "他先问目标，再问约束，最后问时间" |
| 2 | **判断标准** | 找他评价事物的词和依据（"这个好，因为…"） | "他判断方案好坏只看'能不能在两个月内验证'" |
| 3 | **反例** ⭐ | **他反对什么、拒绝什么、说"不要这样"** | 信息量最大，见下面第六节 |
| 4 | **边界** | 什么情况下对方的方法**失效**、对方自己承认过什么局限 | "这套方法只适用于有存量数据的场景" |
| 5 | **语言指纹** | 句长中位数、比喻来源域、高频词、标点习惯 | 可量化的参数表 |
| 6 | **结构骨架** | 他写/说东西的固定模板 | 三幕、总分总、问题-方案-代价 |
| 7 | **决策规则** | 条件 → 动作的对照表 | 同 `TAKE.md` 五维的第 4 维 |

**七种里，3（反例）和 4（边界）最容易被跳过，也最值钱。**

### ④ 对撞：找矛盾、找例外

- **同一材料内**：他前后说法一致吗？有没有自相矛盾的地方？
- **跨材料**：早期和晚期观点变了吗？变了就是有演进，要标出来
- **跟别人**：他和同类方法的分歧点在哪？（分歧处往往藏着最独特的判断）

**发现矛盾不要"抹平"，要并列保留并标注。** 用一句折中话把两个相反观点糊过去，是最常见的失真。

### ⑤ 验证：三法，至少用一法

| 方法 | 怎么做 | 能验什么 |
|---|---|---|
| **盲测** | 拿一份没参与蒸馏的新材料，让你和原主（或原书）各自处理，比对 | 语言/结构层 |
| **回放** | 拿历史上真实发生过的问题，看蒸馏产物给出的答案是否与原主一致 | 判断层 ⭐ |
| **对照** | 蒸馏产物 vs 已知的同类方法，看它有没有独特的判断 | 区分度 |

**没验证的蒸馏，只是"我觉得像"。** 见 `MERGE.md` 的 replay 要求，逻辑一样：**看翻转，不看总分。**

### ⑥ 封装：产物必须是能直接用的

```
❌ "对方的思维很系统"（没法用）
✅ "遇到新问题时的三个固定动作：① 先问目标 ② 再问约束 ③ 给出两个方案并说明各自代价"（能照做）
```

**判据**：别人拿到这份产物，**不看原文**能不能照着做？不能 → 没蒸完。

## 三 · 多视角交叉（防"越蒸越窄"）

**单一视角蒸馏会导致"分布崩溃"** —— 抽出来的东西越来越像同一个模板，失去了对象的丰富性。

【来源：MIND 论文，arXiv 2601.03717】八种认知视角，蒸馏时可以逐个套一遍：

| 视角 | 问什么 |
|---|---|
| 形式符号 | 能不能写成公式/伪代码 |
| 直觉 | 他自己怎么"感觉"这件事 |
| 分解 | 他会不会拆成更小的子问题 |
| 类比 | 他用什么已知事物来打比方 |
| 苏格拉底 | 他会不会反问、逼对方想清楚 |
| 对比 | 他会拿什么来对照 |
| 反事实 | 他会不会问"如果不这样会怎样" |
| 规划 | 他会不会先排步骤再动手 |

**不必八个都用。** 但至少问一句：**这个对象最强的那个视角，我用到没有？**

## 四 · 失败比成功信息量大（这条最反直觉）

【来源：EvoSC，arXiv 2026】

> 同一类任务的成功长得都一样，**失败才会在关键决策点上分岔**。

**做法**：蒸馏时把**失败案例和成功案例配对**，问"逻辑在哪一步分叉的"。

**为什么**：
- 只收成功案例 → 你得到的是"他做对了什么"，但不知道"他为什么没做错"
- 收到失败和反例 → 你才能画出对方的**判断边界**

**落到七种手法上**：第 3 种（反例）和第 4 种（边界）的权重，应该比第 1、2 种更高。

---

## 五 · 蒸馏失败的六种典型

| 失败 | 症状 | 根因 | 避法 |
|---|---|---|---|
| **做成模仿秀** | 像但没用，一问具体就露馅 | 只抽到语言层和结构层 | 必须抽判断层 |
| **抽成鸡汤** | 全是"要系统思考""要抓本质"这种话 | 抽的是他的**价值观口号**，不是他的**操作** | 每个原则后面必须跟一个具体动作 |
| **样本同质** | 出来的是"他在这件事上的做法" | 取样全在同一场景 | 跨场景取样（见①） |
| **抹平矛盾** | 早期和晚期观点被糊成一句话 | 怕麻烦 | 并列保留 + 标演进 |
| **没边界** | 让人觉得他的方法万能 | 没找反例 | 反例和边界是必做项 |
| **没验证** | "我觉得挺像" | 跳过第⑤步 | 至少跑一次回放 |

## 六 · 和外部那些配方的关系（重要）

外面那些技能（女娲 / book-distill / author-style-distill）**不是竞争对手，是预设好的配方**：

```
古月 DISTILL.md   = 骨架 + 参数（能自己配新配方）
女娲 / book-distill = 已经配好的成品（某类对象的完整流程 + 质量门 + 模板）
```

**用法**：
- 对象能对上现成配方 → **直接用那个技能**，别自己从头蒸（它的质量门更细）
- 对象对不上，或者要蒸的东西跨类（比如"一位作者的产品判断力"）→ **用本文件的六步骨架**
- 用骨架蒸出来的东西，如果反复用得上，**再反向固化成一个新配方**

**这就是这套东西能越用越强的原因**：骨架不变，配方可以一直加。
