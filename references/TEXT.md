# 文本区：文章、书、笔记、转录稿、邮件、论坛帖

> **什么时候读**：进来的是**能逐字读的文字**（文章、书、笔记、转录稿、邮件、论坛帖）时读。进来的是带版面的 PDF → 先去 `DOCUMENT.md` 取文字。

进来的是**字符**：能解码、有顺序、可逐字引用。本区动词是"读"，不是"识别"，不是"取证"。产物是规则卡、检查表、决策树，每条带字符区间落点。

## 1. 判定

三条同时满足才进本区：

1. 主体是自然语言连续文本——不是代码、不是结构化数据、不是聊天记录
2. 能按某种编码完整解码，且解码后人能读（UTF-8 / GBK / GB18030 / UTF-16 均可）
3. 有可引用的顺序坐标：字符偏移、行号、段落号至少占一样

### 路由边界

| 像文本但不是本区 | 去处 |
|---|---|
| .md/.txt 里装的是代码、配置、依赖清单 | 代码区（references/CODE.md） |
| CSV / JSON / 日志 | 代码区按数据文件判，不按文章判 |
| 聊天记录 / 会话日志 / 工单 | 对话区（references/CONVERSATION.md） |
| 音频 / 视频原件 | 本区不接；转写走 视频转写工具，拿到文字稿再回来 |
| .eml / .msg | .eml 进本区；.msg 是二进制 OLE，markitdown 未装 msg 支持，报缺口 |
| HTML 网页 | 先 WebFetch / crawl4ai 转正文，落成文本再进本区 |
| 一整棵文本目录其实是工程 | 代码区，用 repomix |

### 四个容易误判

- **假 .txt**：改了扩展名的 PDF/Word。读文件头（`%PDF`、`PK\x03\x04`、`\xD0\xCF\x11\xE0`），不信扩展名。
- **编码骗人**：解码满屏"锟斤拷"或问号，是拿错编码。依次试 UTF-8 → GB18030 → UTF-16（看 BOM）；都不行报缺口，不许把乱码当正文。
- **原件没转写**：用户丢来 .mp3/.mp4 要炼化。本区只接文字稿；转写能力未装，如实报缺口并给 视频转写工具 路径。
- **摘要冒充**：目录、前言、摘要页不是正文。拆单元只认正文区，落点不许落在目录上。

## 2. 取料

按规模选路径，不堆工具：

| 规模 | 工具 | 操作 |
|---|---|---|
| 单篇 < 3 万字符 | Read 直接读 | 整篇进上下文，按段拆 |
| 单篇 3–15 万字符 | Read 分段读 | 手工接续，记清每段起止行号 |
| 超大 > 15 万字符或整本书 | batch-notes-pipeline | 按 chunk 派子代理，主代理只做综合与裁决 |
| 要引用核验 / 覆盖对账 | scripts/digest_batch.py | 只做清点、分段、哈希、引文跨度核验；不调用模型，不证明语义 |

取料纪律：

1. 原料只读不改；要落盘只写到产物目录。
2. 先探编码再全读：前 4KB 试 UTF-8，失败依次 GB18030、UTF-16。
3. 转录稿保留时间戳与说话人标记，它们是落点的一部分；论坛帖保留楼层号——用户名会改，楼层号不会。
4. 邮件拆头与正文：发件人/时间/主题是元数据，正文才是主张来源，分开判。

## 3. 拆到什么粒度

单元 = 一个可独立判断的命题簇。不是一句话，也不是一章。

| 原料类型 | 一级切分 | 二级切分 | 单元定义 |
|---|---|---|---|
| 文章 | 章节/小标题 | 段落 | 1–4 段，200–1500 字符 |
| 书 | 章 | 节 → 论点 | 一个论点及其条件、反例 |
| 笔记 | 条目/日期 | 单条 | 一条 = 一个单元，不拆半句 |
| 转录稿 | 话题段 | 说话人轮次 | 一个完整轮次，50–800 字符 |
| 邮件 | 会话线程 | 单封 | 一封 = 一个单元 |
| 论坛帖 | 帖子 | 楼层 | 一楼 = 一个单元 |

硬数字：

- 单元下限 200 有效字符（不含空白）；不足并入邻接单元，除非它本身是完整短条目。
- 单元上限 1500 字符，超出按论点切开；一个单元最多 3 条主张，超了就是没拆够。
- 段落合并只限同一论点流水；跨小标题合并不是合并，是丢失边界。

## 4. 判什么

每单元按序回答七问，答不出写"未知"，不许跳：

1. **说了什么**：一句可证伪的话。写不出 = 无可炼内容，登记 `no_reusable_knowledge`。
2. **成立条件**：什么前提下它对（场景、时间、对象、口径）。缺条件的主张是半成品。
3. **失效条件**：什么前提下它错。原文的反例、边界、例外逐条抄。
4. **什么档**：观察（原文直述）/ 推断（你推出）/ 未知（证据不足）。三档分开写，不许一段混。
5. **和已知的关系**：新增 / 冲突 / 重复。冲突不许投票合并，并列保留。
6. **变成什么**：被谁用——规则卡的动作、检查表第几条、决策树哪个分支。没有消费者的标 `待判`。
7. **落点在哪**：字符区间 `[start,end)` + 逐字 quote。指不回原文的整条标推断，并写清缺什么。

转录稿加判：发言者身份决定权重，转述与直引分开。论坛帖加判：楼主与反驳楼分开标，"有人说"不等于"楼主实测"。

## 5. 装成什么

下游要执行用规则卡，要验收用检查表，要分诊用决策树。一次任务产出的卡必须同构，否则无法入库对账。

**模板 A：规则卡**

```json
{"id":"rule-<短名>-<n>","trigger":"可观察的入口条件","action":"动词开头，一步一动","boundary":"何时不许用、会失效","counter_example":"原文反例，无则 null","kind":"fact|inference|unknown","evidence":[{"start":0,"end":0,"quote":"逐字，一字不改"}]}
```

**模板 B：检查表**

```json
{"id":"checklist-<短名>-<n>","items":[{"n":1,"check":"可勾选的动作","fail_action":"不过怎么办","evidence":"字符区间"}]}
```

**模板 C：决策树**

```json
{"id":"tree-<短名>-<n>","root":"第一个判断问题","branches":[{"if":"条件","then":"去向","else":"去向"}],"leaves":["终局结论各带落点"]}
```

收据结构用 batch-processing.md 的格式：每条主张挂 `claims[].evidence`，`kind` 三档分标，`conditions / exceptions / uncertainties` 必填，空数组也行，字段不许缺。

## 6. 量化标准

| 指标 | 达标线 | 核法 |
|---|---|---|
| 字符覆盖率 | ≥ 95% 正文有效字符进过某个单元 | 已判单元字符和 / 正文总字符 |
| 落点率 | 主张 100% 带 `[start,end)` + quote | 逐条核 quote 能在原文逐字找到 |
| 三档纯净 | 无混写；unknown 有登记 | 抽 10 条主张人工分档 |
| 消费者齐 | 每条主张能指到卡/表/树的位置 | `待判` 单列成堆，不混进成品 |
| 冲突显式 | 0 静默合并 | 查冲突登记 |
| 未读清单 | 未读 / 失败 / 空内容逐条列出 | 与原料清单对账 |

批量任务用 `digest_batch.py audit` 对账，退出码 0 才算机械完成；语义质量恒标 `not_machine_verified`。

## 7. 失败模式

| 失败 | 症状 | 正解 |
|---|---|---|
| 目录/摘要冒充正文 | 产物引"第三章指出……"但第三章从未进任何单元 | 拆单元只认正文区；落点不许指到目录 |
| 乱码当正文 | 满屏"锟斤拷"、问号、方框，照样往下判 | 先换编码；乱码率 > 2% 的单元整段标 unknown |
| 长文中间遗忘 | 产物只覆盖开头结尾，中间十章无主张 | > 3 万字符必分批；靠覆盖率对账抓遗漏 |
| 观点当事实 | "这个方法最好"直接进规则卡，无 trigger 无 boundary | 补齐谁说、什么条件、何时失效；补不齐标推断 |
| 单元粒度失控 | 一个单元 5000 字符 7 条主张；或每句话一张卡、卡间 90% 重复 | 回到 200–1500 字符、≤ 3 主张；重复卡标 `duplicate_no_increment` 并写 `duplicate_of` |
| 引用指不回 | 落点写"第 3 页"，但纯文本没有页码概念 | 文本区只用字符区间 + 行号；页码是文档区的事 |
