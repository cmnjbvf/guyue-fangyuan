# 实战手册：要怎样，不要怎样

这份文件只写一件事：**别人踩过的坑，别再踩。**

## 十条要

1. **要按构成判区，不按扩展名。** `.pdf` 可能是扫描件、可能是纯文本换了皮。先试提取一段看像不像话。
2. **要先算料再动手。** 用 QUANTIFY 折算档位。T0 的活别上 T3 的架势。
3. **要给每个结论找落点。** 文本给字符区间，文档给页码，代码给 `文件:行号`，软件给地址/证据 ID，对话给消息 ID。
4. **要把"观察 / 推断 / 未知"写字面上。** 不是心里分，是产物里分。
5. **要在原料之外产出。** 产物必须能被下一次任务直接用掉：规则、模板、检查表、代码、结构图。
6. **要如实报缺口。** 缺引擎、缺格式支持、读不了，三条一起给：缺什么、补它要什么代价、不补怎么降级。
7. **要切块并行。** 大活派子代理，但派活时把路径、产物格式、验收标准一次写全——子代理看不到本次对话。
8. **要主代理收口。** 子代理只交原料，去重、冲突裁决、综合、定稿全部留在主代理。
9. **要留未覆盖清单。** 明确写清哪些没看、为什么没看。
10. **要原料只读。** 炼化过程不改原始文件；写只写到产物目录。

## 十二条不要

| 不要 | 为什么 | 改成 |
|---|---|---|
| 一次读完所有参考文件 | 上下文烧一半，关键细节被无关内容盖住 | 只读本次落在的那一区 |
| 把总结当炼化 | 总结是压缩，炼化是可复用 | 产出必须是能直接用的零件 |
| 拿二手解析当原始材料 | 炼出来的是作者的理解，不是事实 | 剥掉加工层找原文；找不到就标"二手" |
| 拿目录、摘要、文件名冒充正文 | 最严重的失败：看起来有产出，实际全错 | 读不进就报"读不进" |
| 大仓库直接全量打包 | 爆上下文 + 关键代码埋在中间会被漏 | >5k 行先索引再钻取 |
| 分类纠结太久 | 判错区只换工具，不换标准 | 三问定位，30 秒内决定 |
| 冲突用多数票抹平 | 多数不等于对，被抹平的那条往往是例外 | 并列保留，写清各自范围与来源 |
| 子代理回报全文 | 每个回报都吃主代理上下文 | 要求只交结论 + 落点 + 未决 |
| 为了完整而完整 | 100 万字全过一遍 ≠ 有用 | 边际产出 <5% 就停 |
| 同一材料反复读 | 最常见的假勤奋 | 读不出新东西就停 |
| 产物里塞正确的废话 | "该模块负责业务逻辑"这种句子等于没说 | 随机挑三句能否被证伪，一句都不能就删 |
| 顺手改别的文件 | 用户明确禁止；改动无法追溯 | 改 A 只动 A |

## 本机环境坑（会直接卡死任务，不是建议是事实）

| 坑 | 症状 | 解法 |
|---|---|---|
| PowerShell 工具 stdout 被吞 | 命令退出码 0 但没有任何输出 | 结果 `Set-Content` 到 `$env:TEMP\*.txt`，再用 Read 读 |
| Git Bash 路径传给 Windows 程序 | `/d/xxx` 被解析成 `D:\d\xxx`，报"路径不存在" | 一律写 `D:/xxx`，或加 `MSYS_NO_PATHCONV=1` |
| pip 卸载被安全策略拦 | 卡在 `Uninstalling xxx` 十几分钟不动，日志里有 `[safe-delete] SAFE_DELETE_FAIL_CLOSED` | **不要强杀**（强杀会导致包被卸掉、新版没装上）。补装用 `--no-deps --no-cache-dir` |
| `markitdown[all]` 装不上 | 拉 Azure SDK，`azure-core` 本机无可用版本 | 只装 `[pdf,docx,pptx,xlsx]` |
| 子代理模型名写缩写 | 调用成功但模型没换，静默吞掉 | 传模型选择器里的显示名，一字不差 |
| 同一文件并行 Edit | 后写的覆盖先写的，改动消失 | 同一文件改多处时串行 |
| 中文路径 + 老式 Windows 工具 | `aidl.exe` / `aapt.exe` 报 `Illegal byte sequence` | 先复制到纯 ASCII 路径（如 `D:\tmp_build`）再跑 |
| Bash 里出现 "PowerShell" 字样 | 被安全策略拦 | 用 PowerShell 工具本身，不在 bash 里拼字符串 |
| 模型频率限制 | 子代理创建报 429 | 换模型重试，或自己串行做 |

## 新增前先查重（防技能库腐化）

炼化出来的东西越攒越多，最大的风险不是不够，是**重复**。重复一多，执行时不知道用哪个，最后哪个都不用。

任何新增之前，先走三步：

1. **本技能内查**：把要新增的内容压成一句话，去现有 references 里找有没有讲过。有 → 不新建。
2. **跨技能查**：这条能力是不是别的 skill 已经在做？用目录名和 description 扫一遍。有 → 在产物里指向它，不要复制一份进来。
3. **三选一**：
   - **Refine** —— 现有文件能装下，就改那一份，哪怕要动它的结构
   - **Create** —— 确实没有承载点，才新建
   - **Skip** —— 已经有了，直接跳过，并在产物里写"复用 X"

**唯一判据**：这段内容能不能被现有文件的某一节概括？能，就改那一节；不能，才新建文件。

**怎么查，给可执行的两条（别靠眼睛）：**

1. **本技能内**：把每份 md 按 `。\n；` 切句，取长度 ≥25 字的句子，统计哪些在 2 个以上文件里出现。重复解释会立刻暴露。实测本技能 19 份文件只有 2 条命中，其中 1 条是表头结构、1 条是必要呼应（同一原则两个区各要说一次，读单区的人也得看到）——**所以"有重复"不等于"该删"，要看删了会不会断信息**。
2. **跨技能**：`ls ~/.workbuddy/skills/`，读每个目录的 description 首句，找同义能力。命中就先问一句：这条能力是不是它已经在做？是就在产物里指向它。

反面案例（本机真实情况）：`book-distill`、`distill-novels`、`author-style-distill`、`writing-dna-skill`、`cangjie-skill`、`multi-copywrite-alchemy`、`nuwa-skill` —— 七个都在做"把文本蒸馏成风格/方法"。再多建第八个，就是往沼泽里再倒一桶水。

## 自优化的变更纪律（谁在改、什么能改）

达尔文这类优化器会持续提改动建议。**不是所有建议都该采纳。** 判断标准只有一条：**这个改动是让执行更准，还是让文档更漂亮？**

| 可以改 | 理由 |
|---|---|
| 具体性（模糊措辞 → 具体参数/示例） | 直接减少执行偏差 |
| 失败模式（补"如果 X 失败 → Y"） | 减少卡死 |
| 检查点（补显性闸门） | 防止跳步 |
| **内部矛盾**（同一事实两处说法不一） | 矛盾会让执行者二选一，必错一个 |
| **顺序错**（先做什么后做什么） | 实测出来的顺序比想出来的准 |

| 不能改 | 理由 |
|---|---|
| 用户定的阈值（T1=2 万字、锚定率 90%） | 按用户的实际使用场景定的，不是论文结论 |
| "别反复问用户"这条 | 与用户的明确要求直接冲突 |
| 原料只读不改 | 安全底线 |
| 已删文件的溯源记录 | 删了就不知道东西去哪了 |

**两条硬规矩：**

1. **评委的结论必须复核。** 实测撞到过一次：评委断言"触发词漏了拆解"，实际 grep 发现六个词全在。LLM 评委准确率 46.4%（SkillLens 数据），跟抛硬币差不多——**它说的每一条都要回去查原文**。
2. **一轮只改一处**，改完 commit + push。多改一处，分数涨了也说不清是谁的功劳。

## 读到回执之后（怎么判断改不改）

回执最后一行「归属」决定动作，**不是所有回执都要改技能**：

| 归属 | 先做什么 | 改不改 |
|---|---|---|
| `skill 缺口` | 复现一次，确认不是偶发 | 改。但先看现有文件能不能装下（能装就改那节，不新建） |
| `环境缺工具` | 确认工具真没有，不是路径写错 | 改 `TOOLS.md` 的能力边界，写清降级路径 |
| `材料本身残缺` | 看产物里标了"未覆盖"没有 | 不改技能。只检查标注诚不诚实 |
| `我判断错了` | 回到当时的分区/定档依据 | **改判据措辞，不改结论**——结论可能对，是规则没说清 |

三条纪律：

1. **别为一条回执改全局。** 一次卡点可能是特例；同类出现三次以上，才动规则。
2. **改之前先搜。** 同一问题的答案可能已经在别的文件里，只是没接上（轮 1 就是这么发现的：CONVERSATION 缺的不是新内容，是指向 batch-processing 的链接）。
3. **改完回写。** 在原回执条目下加一行 `已处理：<commit 短哈希>`，否则下次会重复处理同一条。

## 不可逆操作：先备份，再拆备份

六类动作算不可逆：**删除 / 覆盖 / 移动 / 格式化 / 批量改名 / 清空数据**。

判断只有一句：**这一步做完，原件还回得去吗？** 回不去就进流程。

### 四步，不许跳

1. **判** —— 明确写出这次要动哪些路径、什么动作。写不出来说明还没想清，别动手。
2. **备** —— 复制到**原目录之外**，命名带时间戳：
   ```
   cp -r "D:/原件目录" "D:/备份区/原件名-20261021-0330"
   ```
3. **核** —— 单文件比 SHA256，目录比**文件数 + 总字节**。对不上就重新备，不许"差不多就行"。
4. **拆** —— 之后的读、改、拆解**全部在备份上做**。原件保持原样。交付时写一句：`原件未动，产物基于备份 <路径>`。

### 三条禁令

| 禁令 | 为什么 |
|---|---|
| 不在原目录里建 `.bak` | 清理原目录时会被一起删，等于没备份 |
| 不"边改边备份" | 改到一半才发现备份失败，原件已经变了 |
| 不当 `mv` 是备份 | 移动不是复制，原件位置已经变了 |

### 备份什么时候能删

**用户明确说可以删之前，不删。** 空间紧张可以提一句，但决定权在用户——备份是他最后的退路。

### 已经在 git 里的东西

技能目录本身有 git，commit 就是备份，不用额外备。**git 覆盖不到的地方才是这条规则的目标**——用户的项目文件、桌面资料、别人的仓库。

## 先打样，再量产（实测：返工吃掉 57% 的时间）

批量产出前必须走"1 → 2 → N"，不许直接上 N。

| 步 | 做什么 | 通过标准 |
|---|---|---|
| **1 张** | 按设想写完第一张，停下来自己通读 | 字段齐、落点能指回、能被证伪 |
| **2 张** | 换一个不同类型的原料再写一张 | 两张结构一致，能并排放 |
| **N 张** | 才开批量 | — |

**实测代价**：某单 04:03 开始写卡、04:04 才写出写作规范，比第一张卡晚 34 秒。结果前 3 小时做完 468 张，**后 4.4 小时全在返工修 frontmatter**（脚本名就叫 `s04_repair_fm.py`）——返工占总时长 **57%**。

**三条判据，任何一条不满足就不许开批量：**

1. 模板能写成一份文件吗？写不出来 = 你还没想清楚要什么
2. 第 1 张和第 2 张能并排放、结构一致吗？不一致 = 规范还浮着
3. 落点写法定死了吗？（字符区间 / 页码+区间 / 文件:行号 / 消息 ID）——**批量里换落点写法 = 全部返工**

## 派子代理（并行加速的唯一正当理由）

串行慢是因为一件事一件事做；并行的收益只在大批量、且**标准已经定死**时成立。

### 一、三问全过才派

1. **切得开吗**——按内容边界切（不同来源 / 不同章节 / 不同族），不按字数硬切
2. **规范定了吗**——**没打样就不许派**。标准没定死就派 8 个，会拿到 8 份格式不同的产物，合并成本高于串行收益
3. **量够大吗**——单 agent 半天能干完的别派。派活有固定开销：写清 prompt、收回报、验产物

三问有一条不过，就自己串行做，并在产物里写明**为什么没并行**。

### 二、怎么切

| 切法 | 何时用 | 例子 |
|---|---|---|
| **按来源** | 多个独立目录/文件 | 11 个源目录 → 派 N 个，一人一片 |
| **按章节** | 一本大书、一部合集 | 按卷或主题块 |
| **按族** | 产物本身分类型 | 机制卡 / 架构卡 / 事件卡各一个 |
| **按字数** | — | ❌ 硬切会把一句话切成两半，还制造跨批依赖 |

### 三、派活模板（照抄，缺一样不派）

```
你是「<角色>」。目标：把 <绝对路径> 炼成 <产物形态>。

范围：只处理 <这批文件/章节>，其余不要碰。
产物：写到 <绝对路径>，格式照 <样板文件绝对路径>。
验收：<可核对判据，如「每张卡有来源锚点且能回查」>
回报：只交三样——结论清单 / 落点 / 未决问题。不贴原文，不复述。
```

**最关键的是「格式照 <样板路径>」这一行。** 没有样板就派，等于让 8 个人各自发明格式——这正是批量返工的来源。

### 四、收活三查

子代理说“写完了”不等于写对。**抽查，不只看行数**：

1. **抽内容**：随机挑 2–3 个产物，看落点能不能回查到原文
2. **查一致性**：多个 agent 的产物能不能并排放、结构一样
3. **查账**：它报的“已处理 N 个”和实际数对得上吗

任何一项不过 → 退回重派，或自己补，**不许把没验的产物直接合并**。

### 五、并发与成本

- 并发数没有硬上限，**真实约束是主代理的上下文**——每个回报都占一份
- 所以回报必须砍到「结论 + 落点 + 未决」；要全文等于白派
- 模型按活配：调研/判断类用好模型，机械提取/格式转换用便宜的
- 派活必须带**明确终止条件**，不许“你觉得够了就停”

### 六、综合权不外放

子代理只交原料。**去重、冲突裁决、跨批合并、最终结论**全部留在主代理。

理由很实际：8 个 agent 各自去重，合并时会发现同一件事有 8 个版本且互相矛盾——**统一口径只能由一个人做**。

## 防偷懒：六条可执行的约束

**偷懒不是态度问题，是阻力最小路径问题。** 它会选“看起来交付了、又不容易被抓”的做法。六条堵住它。

### 1. 开工前报工时，不许闷头干

先给一句：`这活约需 <X> 小时 / <N> 批`，并说清按什么口径算（多少次模型调用、每批多大）。

用户看到“40 小时”能改范围、能分批、能不做。**这比 8 小时后收到“完成一半”强得多。**

### 2. 完成定义写成可数的

| ❌ 不可数 | ✅ 可数 |
|---|---|
| 把分析层读完 | 2,498 篇逐篇有收据：446 篇出卡、2,052 篇标“无增量”并给理由 |
| 整理好资料 | 11 个源各出一份来源地图，未读部分具体到目录与体量 |

**可数才可验，可验才没法糊弄。**

### 3. 交付带可独立核验的清单

不是“我读了 446 篇”，而是“这 446 篇的路径清单在这里”。

**只报数字不给清单 = 用户没法数、没法抽 = 等于没报。**

### 4. 覆盖率必须能被独立复算

账本里的数字，用户要能用文件系统自己算出来。所以账本必须给出：

- **分母从哪来**：manifest / 清单的绝对路径
- **分子怎么数**：已处理清单的路径

给不出来就说明账是估的。

### 5. 中途报进度，不许到最后才说

每完成一个批次（或 25%）报一次：已完成什么、还剩什么、预计还要多久。

**闷头干到结束才说“只做了一半”，是最坏的情况**——用户连止损的机会都没有。

### 6. 把“慢”和“漏”分开定价

明确写进任务口径：**慢是正常的，漏是不可接受的。**

| 情况 | 判定 |
|---|---|
| 40 小时，全部读完 | ✅ 正常 |
| 8 小时，读了 18%，**开工前就说了** | ⚠️ 可接受，是双方同意的取舍 |
| 8 小时，读了 18%，**结束时才说** | ❌ 失败（哪怕账写得诚实） |
| 8 小时，读了 18%，报告写“已完成” | ❌ 最严重 |

**AI 会感知压力**：用户催得急，它就少读一点、报告写漂亮一点。所以要显式声明：宁可慢，不许漏。

## 脚本替模型：哪些活不该让模型干

**唯一判据：这件事有没有唯一正确答案？** 有 → 脚本；没有 → 模型。

| 该用脚本 | 为什么 |
|---|---|
| 清点文件、统计体量 | `find` + `wc`，秒级；模型数不准还费 token |
| 内容去重 | 哈希比对，确定性 |
| frontmatter 校验（字段齐全、格式对） | 规则明确，脚本比模型稳 |
| 批量重命名 | 改名规则能写成代码 |
| 覆盖率计算 | 分母分子都要可复算 |
| 提取固定模式（日期、ID、路径） | 正则比模型准且可复现 |

| 不该用脚本 | 为什么 |
|---|---|
| 判断这篇有没有新信息 | 要理解语义 |
| 写卡片 | 要提炼 |
| 冲突裁决 | 要权衡 |
| 跨批综合 | 要有全局视野 |

### 一条实用规矩

**凡是能写成一句 `if` 判断的，都交给脚本。**

模型只干“需要读懂才能判断”的活。这样既快又稳——**脚本输出可复现，模型输出每次都不一样**。

### 别自己造轮子

技能自带 `scripts/digest_batch.py`（清点 / 分段 / 哈希 / 收据 / 对账），纯标准库，不用装依赖。

只有它覆盖不到时才写新脚本。新脚本也放 `scripts/`，**不散落在产物目录里**——散落就等于下次找不到，等于没写。

### 实测对照

某单为 2,498 篇文档写了 5 个脚本（清点 / 分诊 / 校验 / 修 frontmatter / 构建）。这些活如果交给模型逐篇做，按每篇 10 秒算要 **7 小时**；脚本跑完是 **分钟级**。

反过来，那单的返工 4.4 小时恰恰是"边干边改格式"造成的——**能用脚本校验的格式问题，拖到人工返工才发现。**

## 开工前 30 秒自检

1. 它落在哪一区？——只读那一份手册
2. 折算后多大？——定 T 档
3. 是原始材料还是二手？——二手先剥一层
4. 有没有可用的工具？——没有就报缺口，别硬来
5. 这次要产出什么形态？——先说清再动手
