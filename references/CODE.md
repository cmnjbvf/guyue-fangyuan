# 代码区：源码仓库、脚本、配置、依赖清单

进来的是**符号**：能执行、能配置、改了会改变系统行为。本区动词是"拆结构与追调用"，不是"通读全文"。产物是模块卡、规则条目、依赖与假设清单，每条落 `文件:行号`。

## 1. 判定

三条同时满足才进本区：

1. 主体是机器可读的指令或声明——源码、脚本、配置、依赖清单（package.json / requirements.txt / go.mod 等）
2. 内容可运行或可配置某个系统；改动能改变程序行为
3. 有可引用的结构坐标：文件路径 + 行号

### 路由边界

| 像代码但不是本区 | 去处 |
|---|---|
| 讲代码的文章、教程、源码分析帖 | 文本区（references/TEXT.md），判文字不判代码 |
| 二进制、安装包、APK、ASAR、固件 | 软件区，走 REA 取证 |
| 代码的截图、图片 | 文档区先 OCR / 多模态取字，拿到文本再回本区 |
| 聊天记录里贴的代码片段 | 对话区；片段只作佐证，不单独炼 |

### 容易误判

- **假配置**：.json/.yaml 里装的是数据不是配置——没有消费方读取、不改行为的，按数据文件判，只炼结构不炼规则。
- **产物当源码**：dist / build / node_modules 里的文件是生成物，源码在别处；拿生成物当业务逻辑分析，结论全部作废。
- **依赖清单≠代码**：package.json 只声明"要什么"，不声明"怎么用"；依赖清单的产出是约束清单，不是模块卡。

## 2. 取料

本机现役工具，四件，不堆：

| 工具 | 用途 | 用法 |
|---|---|---|
| Glob | 按模式列文件，摸仓库形状 | `**/*.ts`、`src/**` |
| Grep | 搜符号、字符串、调用点 | 正则 + glob 过滤 |
| Read | 读单文件，带行号 | 一次一个文件，记行号 |
| Repomix 1.18.1 | 中小仓库整体打包成 XML | `cd /d/tools/repomix && node node_modules/repomix/bin/repomix.cjs "D:/路径" --output "输出.xml" --style xml` |

Repomix 三条纪律：

1. **必须传 Windows 风格路径**（`D:/xxx`）。Git Bash 的 `/d/xxx` 会被 Windows 程序解析成 `D:\d\xxx`，报路径不存在。
2. 输出写到产物目录，不写进原料仓库。
3. 打包前先定 ignore 名单，`node_modules`、`dist`、`.git`、`build` 一个不留。

规模不够不上 Repomix：1–5 个文件直接 Read，打包是浪费。code2prompt（Rust 单二进制，模板化打包）本机未装，不写用法；其模板化输出思想已由 `--style` 覆盖。

## 3. 拆到什么粒度

先按总行数分档，再在档内拆模块。

| 规模 | 取料路径 |
|---|---|
| 1–5 个文件 | 直接 Read 全读 |
| < 5k 行 | Repomix 全量打包 |
| 5k–50k 行 | 只打包核心子树，排除 node_modules/dist/.git |
| > 50k 行 | 先出结构索引，再按问题钻取 |

**全量打包在大仓库上是负收益**：上下文被撑爆，且关键代码埋在中间会被漏掉三成以上（"中间遗忘"）——塞得多不等于读得到。

>50k 行的结构索引做法（借鉴 aider 的 repo-map 思想：tree-sitter + PageRank 出约 1k token 导航图；本机无 tree-sitter 工具链，用 Glob + Grep + Read 出等价索引）：

**第一步：按行数排序，不按目录树。** 真实仓库的代码量高度集中——`某个对话机器人项目/src` 实测 163 个文件、50,512 行，**前 21 个（12.9%）占了 43.7%**。

1. 跑一遍 `文件 → 行数` 的全量统计，降序排
2. 只看前 10–20 个：注释首行写着职责，`export` 行写着对外接口——读这两处，不读全文
3. 记规模分布（≥1000 / 500–999 / 100–499 / <100 各几个）：核心少、长尾多 = 成熟工程；反过来 = 还没重构

**第二步：画目录树。** 到二级，每目录一行职责。

**第三步：入口与承诺。**
1. 入口文件清单：main / index / cli / server，各带 `文件:行号`
2. 每个顶层模块一句话：被谁调用、对外承诺什么

目录树放在行数之后画，因为先看目录容易被命名骗——叫 `utils/` 的可能装着核心逻辑，行数不会骗人。

仓库内单元 = 一个模块：一个目录或一个主文件 + 它的直接依赖。判断标准：能用一句话说清"改它会引爆什么外部行为"；说不清就是没拆够，继续往下切。一个模块卡只覆盖一个主文件，跨目录的合并写进上层模块。

## 4. 判什么

每个模块按序回答七问，答不出写"未知"，不许跳：

1. **入口在哪**：谁调用它——外部入口、被依赖方、调度方，各带 `文件:行号`。
2. **对外契约**：输入是什么、输出是什么、失败时返回什么。一句话可证伪。
3. **成立条件**：什么环境、配置、时序下它对。环境变量、配置项、目录假设逐条列。
4. **失效条件**：什么输入、什么状态下它错。异常路径、边界值、降级行为。
5. **爆炸半径**：改这个模块会引爆哪些外部行为——按调用方清单数。
6. **隐式契约**：代码没说但依赖的东西——文件系统状态、时钟、网络、第三方服务可用性。
7. **落点与档位**：落 `文件:行号` + 关键行逐字 quote；分观察（代码直述）/ 推断（你推出）/ 未知（没读到），三档分开。

配置与依赖清单改判四问：这个配置被谁读（消费方 `文件:行号`）、默认值是什么、缺了会怎样、哪个环境覆盖它。

## 5. 装成什么

一次任务产出的卡必须同构，否则无法对账入库。

**模板 A：模块卡**

```json
{"id":"mod-<短名>-<n>","name":"模块名","one_liner":"一句话职责","entry":"文件:行号","contract":{"in":"","out":"","on_fail":""},"holds_when":["条件"],"fails_when":["条件"],"blast_radius":["被牵连的外部行为"],"implicit_assumptions":["假设"],"kind":"fact|inference|unknown","evidence":[{"file":"","line":0,"quote":"逐字"}]}
```

**模板 B：规则条目**

```json
{"id":"code-rule-<短名>-<n>","trigger":"可观察的入口条件","action":"动词开头，一步一动","boundary":"何时不许用、会失效","counter_example":"代码中的反例路径，无则 null","kind":"fact|inference|unknown","evidence":[{"file":"","line":0,"quote":""}]}
```

**模板 C：依赖与假设清单**

```json
{"id":"dep-<短名>-<n>","explicit":[{"name":"","declared_at":"文件:行号"}],"implicit":[{"assumption":"","breaks_if":"","evidence":"文件:行号"}],"unverified":["没读到、没跑过的项"]}
```

模块产 A；从代码归纳出的做法（"改 X 必须先动 Y"）产 B；配置与依赖清单只产 C。收据结构对齐 batch-processing.md：`claims[].evidence` 挂文件:行号落点，kind 用其五类词表（观察→`fact`、推断→`inference`）。**本区收据是概念模板，不走脚本校验**——但逐字 quote 与行号必须可回查。`conditions / exceptions / uncertainties` 必填。

## 6. 量化标准

| 指标 | 达标线 | 核法 |
|---|---|---|
| 落点率 | 主张 100% 带 `文件:行号` | 逐条核 quote 能在该行逐字找到 |
| 无锚点占比 | < 20%，且全部标推断 | 数 evidence 为空的条目 |
| 模块卡覆盖 | 核心子树模块 100% 有卡 | 卡清单 vs 结构索引对账 |
| 单卡体量 | ≤ 30 行；契约一段话说完 | 超了就是没拆够 |
| 三档纯净 | 无混写；unknown 有登记 | 抽 10 条人工分档 |
| 索引体量（>50k 行仓库） | ≤ 150 行；钻取轮次与问题一一对应 | 数索引行数、数钻取记录 |

## 7. 失败模式

| 失败 | 症状 | 正解 |
|---|---|---|
| 大仓库全量吞 | >50k 行直接打包，上下文爆了，结论只剩开头结尾 | 先出结构索引再按问题钻取；全量打包只给 <5k 行 |
| 路径踩坑 | Repomix 传 `/d/xxx`，报 `D:\d\xxx` 不存在 | 一律传 Windows 风格 `D:/xxx` |
| 生成物当源码 | 分析半天是 dist/ 里的编译产物，结论对不上源码 | 打包前 ignore node_modules/dist/.git/build |
| 抄录当分析 | 模块卡贴满实现细节，没有契约、没有失效条件 | 卡里只放行为契约；实现细节只留锚点 |
| 结论无锚点 | "这个模块大概负责鉴权"，指不回 `文件:行号` | 无锚点标推断并写清缺什么；三档分离 |
| 文章当代码 | 拿一篇"XX 项目架构解析"产出代码规则，规则在原文里不存在 | 判定先分"文字谈代码"与"代码本身"；前者去文本区 |
