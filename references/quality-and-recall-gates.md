# 消化与蒸馏质量

收尾前或需要评估批次时读取。根据通用交付或领域知识库分支选相应检查，不让专用门禁阻塞无关领域。

## 通用交付

- 目标：输出位于指定对象，回应用户用途，没有按来源领域强制重路由。
- 输入：原件、已取得正文、未取得正文和失败分别列清；大批次每段都有处理收据或明确待处理状态。
- 证据：主张可回查，合成上下文与原文分开；字段齐全、字符覆盖、引文字面匹配均不证明语义正确。
- 语义：检查关键条件/否定/反例/时间单位是否保住，冲突是否保留，合并是否损失增量；不以检索命中证明消化完整。
- 使用：用户实际问题能否用产物解决单独验证。没用真实资料或任务就标未验证。

小任务用相称的人工核对；大批量使用批处理对账加语义复核，不强制所有任务加载数据库、向量库或评审团队。

## 该领域 V2 专用门

### 单卡门

- frontmatter 可解析；ID、标题和分类完整且唯一。
- 摘要、适用、不适用、正向和负向查询与正文一致。
- 无增量重复不建卡。
- 高风险主张的来源、日期、范围、复核期和证据状态满足合同；缺失则阻断激活。
- 关系允许为空，但已写关系必须真实。

## 候选版本门

- 所有卡可读，ID 和规范化标题无重复。
- 准确标题直达必须为全量 100%。
- 新卡准确标题、正向查询进入预期结果；负向查询不乱入。
- 已知误召回、no-match、索引桩和批量失败回归通过。
- 同一查询和同一版本排序可复现。
- active pointer 在候选阶段保持原值。

## 证据分层

依次区分：

1. Skill/frontmatter 静态结构正确；
2. 候选同步器和自动测试通过；
3. 开发冒烟集通过；
4. 正式认证集达到阈值；
5. 真实 Agent 影子任务采用正确；
6. 用户实际产出质量改善。

前一层不能替代后一层。`activation_eligible=true` 不等于 active 已切换；80 条开发集不等于约 200 条正式认证集。

## 失败语义

- `candidate_fail`：候选未获激活资格；保留 staging 和报告。
- `no_match`：没有足够知识证据，不用底座或弱重叠冒充命中。
- `blocked_by_stale`：只命中高风险过期/隔离知识；不得作为可靠事实输出。
- `partial`：存在相关候选但覆盖尚不完整；继续读取或报告缺口。
