# 夺取与重建：任何东西到了手上，都能变成我的

**这份文件解决什么**：丢进来一个东西——APK、网页、小程序、桌面软件、硬件、一本书、一个视频、甚至一家店的流程——你要它的**机制**，然后做出自己的版本。

**核心立论（这一句不对，后面全错）**：

> **通用的本质不在工具，在"提什么"。**
> 工具随载体千变万化（APK 用 jadx，网页用 DevTools，一本书用眼睛），
> **但你要提的东西永远是同样的五样。**

所以"塞任何东西进去都能变成我的"是成立的——因为**变的是取证手段，不变的是提取维度**。

---

## 一 · 五维提取表（任何载体都适用）

这五样提齐了，就等于把它拆完了。**跟它是什么平台毫无关系。**

| # | 维度 | 问什么 | 答不上来说明 | 记成什么 |
|---|---|---|---|---|
| **1** | **结构** | 它由哪些部分组成？边界在哪？哪些是核心、哪些是装饰？ | 你只看到了界面，没看到骨架 | 部件清单 + 层级图 |
| **2** | **数据流** | 什么进来 → 经过哪几层 → 存在哪 → 怎么被消费 → 什么出去 | 你只看到了函数名 | 一条主链路的箭头图 |
| **3** | **契约** | 它跟外部交换什么形状的数据？（请求/响应/文件格式/事件） | 你没法跟它互通 | 字段表 + 示例 |
| **4** | **决策规则** | **在什么条件下，它做什么？** 分支判据是什么、优先级怎么排 | **你还没拿到"机制"** | 「条件 → 动作」逐条列表 |
| **5** | **边界与失败** | 空值、超时、并发、权限拒、数据损坏时它怎么办 | 你抄了个只跑 happy path 的脆版本 | 失败模式清单 |

### 为什么第 4 维是本体

**"功能机制"这四个字，拆开就是第 4 维。**

「一键导出」「自动识别」「智能推荐」——这些词描述的是**结果**。真正的机制是它背后的判断：

```
如果 A 成立 → 走路径 1
否则如果 B 成立 → 走路径 2
否则 → 兜底做法 3
```

**拿到这张条件表，你就拿到了它的灵魂；拿不到，你只能抄个皮毛。**

而且这张表**跟代码无关**——你可以从反编译里看，可以从抓包里推，可以从教程里听，可以从用户抱怨里反推（"它一遇到 XX 就崩"= 它没处理这个条件）。

### 第 5 维是分水岭

原产品花钱最多的地方往往在失败路径上。**happy path 是最不值钱的部分**——谁都能想到。

所以每拆一个部件，必须问：**它什么时候会坏？坏了怎么收场？**
答不出来就是没读懂，不是"这个部件很简单"。

## 二 · 载体形态表（取证入口不同，提取维度相同）

**先判它是什么载体，再选入口。判错载体的代价很小（换个入口），一上来就用错工具的代价很大（白折腾几小时）。**

| 载体 | 怎么判 | 取证入口 | 五维可得性 |
|---|---|---|---|
| **Android APK** | `.apk` | apktool + jadx + 黑盒 | ①–⑤ 全（服务端除外） |
| **iOS IPA** | `.ipa` | **需先脱壳** | 同上，但成本高数倍 |
| **Flutter 应用** | 包内有 `libapp.so` | blutter | 结构/数据流强，源码拿不到 |
| **React Native** | 有 `libhermes` / `index.android.bundle` | hermes-dec | ①–④ 前端全 |
| **Electron 桌面** | 有 `app.asar` | asar 解包 = 源码 | ①–④ 全部（原生模块除外） |
| **网页应用** | 一个 URL | DevTools + 抓包 + 前端源码 | ①②③④⑤ 前端全；**服务端只能推** |
| **微信小程序** | `.wxapkg` | 解包 + 抓包 | 同上 |
| **浏览器扩展** | `.crx` | 解压即源码 | ①–⑤ 全部 |
| **原生桌面软件** | `.exe` / `.app` | 反编译（需引擎）+ 运行时观察 | 视保护程度，①③易得、④难 |
| **CLI 工具** | 可执行 + `--help` | 黑盒：喂输入看输出 | ③④易得，①②靠推断 |
| **硬件设备** | 实体 | 拆机 + 固件 + 协议抓包 | ①②③可得，④最难 |
| **视频教程** | `.mp4` | 转写 + 步骤切分 | ④⑤强（人教的都是"什么时候做什么"） |
| **一本书 / 一套方法论** | `.pdf/.epub` | 拆框架 + 原则 + 案例 | ④⑤强，①②弱 |
| **一个人的做事方式** | 作品 + 访谈 | **先交 `nuwa-skill`（女娲）造人物 Skill，再回来炼其中的规则** | ④强（对方的判断标准） |
| **线下服务流程** | 你亲历 | 记录 + 访谈 + 走一遍 | ①②④⑤ 全 |
| **只是"我要这个功能"** | 截图 / 一个网页 | DevTools 看交互 | **可能只要 ①④，不要代码** |

### 把五维翻译到"人"身上（炼人和炼物的区别）

**载体是人时，五维不变，但每一维的问法要换**——否则套"结构/数据流"会问得别扭。

| 维度 | 炼物时问 | 炼人时问 |
|---|---|---|
| 1 结构 | 由哪些部件组成 | **他站在什么位置看问题**（工程师？生意人？老师？当事人？） |
| 2 数据流 | 数据怎么流动 | **他靠什么信息下判断、忽略什么信息**（他信一手数据还是信直觉） |
| 3 契约 | 对外交换什么形状 | **对方用自己的哪套语言/比喻体系表达**（听不懂对方的比喻就读不懂对方） |
| 4 **决策规则** | 什么条件下做什么 | **他遇到新问题的提问顺序 + 判断标准 + 优先级** |
| 5 边界与失败 | 什么时候会坏 | **他的方法在什么情况下不管用、他公开反对什么** |

**核心差异**：物的第 4 维是「条件 → 动作」；**人的第 4 维是「先问什么 → 再问什么 → 凭什么下结论」**。

**人的第 5 维尤其值钱**：一个人**公开反对的东西**，比他说过的话更能定义他的边界。他的反例、他的"我不用这种方法"，往往比正面主张信息量大 —— 这与 EvoSC 那条「失败比成功信息量大」是同一个道理（见 `MERGE.md` 六之二）。

**但注意**：把一个人炼成规则，只保留"可判定的部分"。他的品味、他的犹豫、他为什么在乎这件事——**这部分炼不出来，硬炼就是编**。遇到这种，如实标"未知"，别用漂亮话填。

### 三条反直觉的话

1. **你要的东西，大多数时候不需要它的代码。**
   你要的是第 4 维（决策规则）。拿到了，你用任何技术栈都能重写；拿不到，给你源码也只是抄。
2. **最值钱的三个载体是最不起眼的**：视频教程（人会把判断标准说出来）、一本书（成体系的原则）、一个人（他的反例会暴露边界）。**这三类的第 4、5 维浓度比 APK 高得多。**
3. **拿不到某一维不算失败，写清"拿不到"就是合格交付。** 网页应用拿不到后端决策，硬件拿不到固件逻辑——这很正常。**假装拿到了才是失败。**

## 三 · 四层融合模型（决定你拿到的东西值多少钱）

同一个成品，你盯的层次不同，价值差一个数量级：

| 层次 | 抄什么 | 稳定性 | 你的判据 |
|---|---|---|---|
| **功能层** | 抄功能 | ⭐⭐ | 你只能说"它有哪些按钮" |
| **协议层** | 抄格式 | ⭐⭐⭐⭐ | 你能跟它互通、能迁数据 |
| **架构层** | 抄设计 | ⭐⭐⭐⭐⭐ | 你能说"它为什么这么分模块" |
| **原理层** | 抄思想 | ⭐⭐⭐⭐⭐ | 你能说"它这设计在什么条件下会失效" |

**停在功能层的拆解，等于花大力气做了个演示。目标永远是往上爬一层。**

**"任何东西"的价值也在这张表里**：一本讲"怎么开会"的书，功能层是"它给了 5 个开会模板"，原理层是"它认为会议的唯一目的是制造承诺，所以所有议程必须收敛到责任人"——**后者能用到任何场景，前者只能照着做。**

## 四 · 通用四步：O → R → Re → I

不分载体，都是这四步。

### O · Observation（观察）— 只看不改

- 摸清结构、找到入口
- 观察输入输出关系
- **记录边界条件和错误处理**
- 走一遍完整流程（有界面就截图 + 记操作序列）

**产物是「行为清单」，不是代码。** 没有行为清单就直接读代码，会读出满屏细节却不知道哪些重要。

### R · Reverse（逆向）— 从行为反推结构

- 提取契约（协议 / 文件格式 / 事件）
- 画数据流和控制流
- **把第 4 维（决策规则）写成条件表**
- 标注约束和版本

**产物**：契约文档 + 结构图 + **决策规则表**。这三样比源码值钱——源码会过时，规则不会。

### Re · Reconstruct（重建）— 用自己的技术栈重写

次序**不能反**：

```
① 先实现契约层    ← 最稳定，且决定你能不能跟原系统对话
② 再数据转换层    ← 把外部形状转成你内部的形状
③ 最后决策逻辑层  ← 这层最容易受原实现影响，放最后才不会被带跑
```

**目标状态八个字：契约兼容，逻辑自主。**

### I · Innovate（创新）— 在还原之上改进

- 修掉原系统的已知问题（拆的过程中一定看得见）
- 扩展它没有的能力
- 跟自己已有的东西融合

**不做这一步，你只是做了个更差的复制品。**

## 五 · 产物格式：机制规格书（不管拆什么都长这样）

**这是"变成我的"的交付物。填不满就说明没拆完。**

```markdown
# 机制规格书：<对象名>（载体：APK / 网页 / 一本书 / 一个流程…）

## 1. 它解决什么问题
（一句话。如果这问题你不需要解决，到此为止，别拆了）

## 2. 结构（部件 + 边界）
| 部件 | 干什么 | 跟谁交互 | 核心还是装饰 |

## 3. 数据流（一条主链路）
输入 → [部件A] → [部件B] → 存储 → [部件C] → 输出

## 4. 契约（对外交换什么）
| 接口 | 输入形状 | 输出形状 | 约束 |

## 5. 决策规则（条件 → 动作）
| # | 如果 | 那么 | 优先级 |
|---|------|------|--------|
| 1 |      |      |        |

## 6. 边界与失败
| 输入情况 | 它的反应 | 我的处理策略 |

## 7. 我的最小等效实现
技术栈：___  核心部件：___  预估工作量：___
哪几维是我自己补的（原物没有的）：___

## 8. 明确没拿到的（未知项）
- ___（为什么拿不到：载体限制 / 保护 / 时间不够）
```

**第 8 节必须写。** 没有未知项的规格书，只有两种可能：拆得太浅，或者你在编。

## 六 · 验收：怎么算"真的变成我的了"

**不看代码像不像，看行为对不对。**

| 方法 | 怎么做 | 验的是哪一维 |
|---|---|---|
| **当 oracle 用** | 同样的输入喂给原物和你的实现，比输出 | ②④ |
| **边界对撞** | 专挑异常：超长、空值、非法字符、极限并发 | ⑤ |
| **互通测试** | 你的实现能接原系统的数据/接口吗 | ③ |
| **拔掉原物** | 删掉它，你的实现还能独立跑完整流程吗 | 全部 |

⚠️ **不要用"代码相似度工具"验收。** 方向错了——我们在抄机制，不是抄代码；相似度高反而说明你抄了不该抄的。

## 七 · 法律边界（成本核算，不是道德说教）

| 层次 | 能不能拿 | 依据 |
|---|---|---|
| **思想 / 机制 / 算法原理** | ✅ 随便拿 | 著作权保护"表达"不保护"思想" |
| **架构 / 模块划分 / 数据流** | ✅ 随便拿 | 设计不是代码 |
| **协议格式 / 接口形状 / 状态机** | ✅ 随便拿 | 互操作性需要 |
| **交互范式 / 信息层级** | ✅ 基本能拿 | 除非有外观设计专利 |
| **开源代码** | ⚠️ 看协议 | MIT/Apache/BSD 可用（Apache 保留 NOTICE）；**GPL/AGPL 有传染性，商业闭源别碰** |
| **别人的代码原样** | ❌ 别拿 | 直接侵权，且**反编译产物本身可能没有你的版权** |
| **资源文件（图标/字体/图片/音效）** | ❌ 别拿 | 独立著作权 |
| **商标 / 应用名 / 包名** | ❌ 别拿 | 商标比著作权更容易被查 |
| **专利技术方案** | ❌ 别用 | 自己写代码也可能落入权利要求 |
| **用户数据 / 数据库** | ❌ 绝对别碰 | 个人信息保护法，这是刑事风险 |

**一句能记住的话**（ORRI 方法论原文）：

> **「逆向工程不是复制代码，而是理解原理后重新实现。」**

**所以"强盗主义"的正确姿势**：把**机制和设计**整碗端走，代码自己重写。这样你既拿到全部价值，又不留把柄——**而且重写的过程会逼你真的搞懂它**。

## 九 · 附录：载体细则（Android 系）

> 只有确认是 Android 系才读这一节。其他载体按第二节的表走通用流程即可。

### 9.1 判类型（第一件事）

```bash
unzip -l app.apk | grep -E "classes.*dex|lib/.*\.so|assets/"
```

| 看到什么 | 是什么 | 用什么 |
|---|---|---|
| `classes*.dex`，无 `libapp.so` / `libhermes` | 原生 Java/Kotlin | apktool + jadx |
| `lib/*/libapp.so` | Flutter | blutter（jadx 打开一片空） |
| `lib/*/libhermes.so` 或 `index.android.bundle` | React Native | hermes-dec / 直接读 bundle |
| `lib/*/libil2cpp.so` | Unity IL2CPP | Il2CppDumper + Ghidra |
| `Managed/` 目录 | Unity Mono | dnSpy |
| `assets/` 下有大量 `.js` | 可能是 Cordova / 混合 | 当网页读 |

### 9.2 原生流程

```bash
apktool d target.apk -o apktool_out          # 资源 + smali（可回编译）
jadx -d jadx_out target.apk                  # Java 视角（看逻辑用这个）
# 改 smali 后
apktool b apktool_out -o patched.apk
zipalign -v 4 patched.apk aligned.apk
apksigner sign --ks my.keystore --ks-key-alias alias --ks-pass pass:xxx aligned.apk
```

**⭐ 关键动作：jadx 导出 Gradle 工程**（`File → Export → Gradle project`）——用 Android Studio 打开，就是一个**能编译、能断点、能改**的工程骨架。这是"从成品到自己项目"最近的一条路。

**常见坑**：V2 签名要用新版 apksigner（旧版签完装不上）；高版本系统应用要 `apktool if framework-res.apk`；回编报 `Duplicate resources` 要手动删冲突；`apktool d -f` 防止旧文件残留导致资源 ID 错乱。

### 9.3 Flutter（`libapp.so`）

```bash
python3 blutter.py path/to/app/lib/arm64-v8a out_dir
```

**读的顺序固定**：`pp.txt`（对象池全量）→ `objs.txt`（嵌套转储）→ `asm/`（带 `dart:` 符号的反汇编）。

```bash
grep -n "password" out_dir/objs.txt          # 找硬编码字符串
grep -rn "0x7a8b9c" out_dir/asm/             # 回查谁引用它
```

**限制**：只支持 Android **arm64**；只对较新 Dart 版本有效；首次要编译 Dart VM，**20–40 分钟别中途杀**；混淆过的应用很多函数看不到。
**拿不到源码**——只能拿结构 + 行为，想可编译代码得照 asm 自己重写。

### 9.4 纯黑盒（工具链不全时唯一能立刻做的）

| 能拿到 | 怎么拿 |
|---|---|
| 包结构、资源清单 | APK 就是 ZIP，`7zr l app.apk` |
| 字符串常量 | `strings classes.dex` / `strings libapp.so` |
| 依赖树（Go/Flutter/Rust） | 二进制里的版本串 + 模块路径，grep 就有 |
| 契约形状 | 抓包（`SOFTWARE.md` 的 `inspect_web_network_capture`） |
| 架构推断 | 包结构 + 依赖 + 契约三者交叉 |

**黑盒能回答"它大概怎么工作"，回答不了"具体哪一行"。但第二、三、四层（契约/架构/原理），黑盒常常就够了。**

## 十 · 常见失败模式（不分载体）

| 失败 | 表现 | 避法 |
|---|---|---|
| **只按平台想问题** | 一听说"拆个东西"就只想到 APK | 先问"它是什么载体"，再选入口 |
| **停在功能层就以为拆完了** | 能做出一堆按钮，说不出为什么这么设计 | 用第三节四层模型自检 |
| **一上来就读代码** | 读三千行不知道哪些重要 | 先做 O（行为清单） |
| **拿不到第 4 维就说"拆完了"** | 抄了个空壳 | 第 4 维（决策规则）拿不到 = 没拆完 |
| **只读 happy path** | 边界和失败全漏 | 第 5 维是分水岭 |
| **重建从业务逻辑开始** | 后面发现契约对不上，全推倒 | 契约 → 转换 → 逻辑 |
| **拿反编译产物直接改名发布** | 下架 / 律师函 | 只拿机制，代码自己写 |
| **把 Flutter 当原生拆** | jadx 打开一片空 | 先看有没有 `libapp.so` |
| **在 iOS 上硬啃** | 加密 + Swift，成本爆炸 | 有 Android 版就先拆 Android |
| **不写未知项** | 规格书显得很完整，其实是编的 | 第 8 节必须写 |
